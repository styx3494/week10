# Windows 端 SMB 連線檢查

## 一句話說明

NAS 端都確認沒問題、電腦還是打不開時，換檢查 Windows 這一端：記住的舊密碼、名稱有沒有解析錯、有沒有重複連線。

## 重點

- 分別用 IP（例如 `\\192.168.1.50\Public`）和 NAS 名稱連線，比較哪一種成功。（來源：raw/05）
- `[唯讀查詢]` 如果 IP 可以、名稱不行：在命令提示字元執行 `ping <NAS 名稱>`，確認 `Reply from` 後面的 IP 和 NAS 的 IP 相同。（來源：raw/05）
- `[可逆變更]` 名稱對到錯的 IP 時，執行 `nbtstat -R` 或重新開機後再試。（來源：raw/05）
- `[可逆變更]` 清除舊的認證：控制台 > 使用者帳戶 > 認證管理員 > Windows 認證，刪除與 NAS（IP 與名稱）相關的項目後重新連線；刪掉後需要重新輸入帳密。（來源：raw/05）
- `[可逆變更]` 確認同一台電腦沒有用不同帳號同時連到 NAS：關閉檔案總管後執行 `net use * /delete /y` 移除所有對應的網路磁碟機，再重新設定。這會中斷所有網路磁碟機，之後需要重新對應。（來源：raw/05）
- 若無法對應網路磁碟機且有啟用 Windows Hello，原廠建議更新 Windows，或改用其他登入方式。（來源：raw/05）
- 檔案總管無法以 UNC 路徑連到名稱以句點（.）結尾的共用資料夾。（來源：raw/05）

## 常見誤解

- 誤解：密碼明明改對了還是被拒，一定是 NAS 壞了。　實際上：Windows 可能還在用認證管理員裡記住的舊認證。（來源：raw/05）

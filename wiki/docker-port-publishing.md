# Docker 連接埠發布（-p）

## 一句話說明

容器像是住在 Docker 主機裡的一個小房間，房門預設是關著的；`-p` 就是在主機外牆開一扇門，把外面的某個門牌號碼（主機連接埠）接到房間裡的門（容器連接埠）。

## 重點

- Docker 預設會擋住沒有發布的連接埠，IPv4 與 IPv6 都一樣。（來源：raw/01）
- 接在 bridge 網路上的容器，所有連接埠都可以從 Docker 主機本身，以及同一個網路上的其他容器連到；但主機外面的裝置連不到。（來源：raw/01、raw/02）
- 要讓主機外面連得到，必須在 `docker create` 或 `docker run` 時加上 `--publish`（簡寫 `-p`）。（來源：raw/01、raw/02）
- 格式是「主機連接埠:容器連接埠」。例如 `-p 8080:80` 代表把 Docker 主機上的 8080 接到容器的 TCP 80。（來源：raw/01）
- 預設是 TCP；要 UDP 時寫成 `-p 8080:80/udp`。（來源：raw/01）
- 可以在最前面加主機 IP，只在那個位址開門，例如 `-p 192.168.1.20:8080:80`。（來源：raw/01）
- 發布時，Docker 會在主機上建立防火牆規則，用 NAT 把主機連接埠對應到容器連接埠。（來源：raw/01）

## 常見誤解

- 誤解：容器跑起來了，網頁就一定打得開。　實際上：沒有用 `-p` 發布的連接埠，主機外面的裝置連不到。（來源：raw/01、raw/02）
- 誤解：`-p 8080:80` 的 8080 是容器裡的連接埠。　實際上：前面是主機、後面是容器。（來源：raw/01）

# Docker 發布範圍：0.0.0.0 與 127.0.0.1

## 一句話說明

用 `-p` 開門時，可以決定這扇門是「對所有人開」還是「只對主機自己開」；寫法不同，家裡其他電腦連不連得到也就不同。

## 重點

- `-p` 沒有寫主機位址時，Docker 會發布到主機的所有位址（`0.0.0.0` 與 `[::]`）。（來源：raw/01）
- 原廠說發布連接埠「預設不安全」：不只 Docker 主機，外面的世界也連得到。（來源：raw/01）
- 在 `-p` 的對應值前加上 `127.0.0.1`（或 IPv6 的 `::1`），例如 `-p 127.0.0.1:8080:80`，可限制為本機存取。Docker 28.0.0 以前，同一 L2 網段的主機仍可能連到發布在 localhost 的連接埠。（來源：raw/01）
- 可以在 daemon 設定把預設綁定位址改成 `127.0.0.1`，讓沒寫位址的發布預設只對主機開放；改 default bridge 的設定後要重啟 daemon。（來源：raw/01）

## 常見誤解

- 誤解：綁在 `127.0.0.1` 就一定只有本機連得到。　實際上：Docker 28.0.0 以前的版本，同一個 L2 網段（例如接在同一台交換器）的主機仍可能連到發布在 localhost 的連接埠。（來源：raw/01）
- 誤解：家裡其他電腦連不到，一定是防火牆的問題。　實際上：也可能是發布時綁了 `127.0.0.1`，較新的 Docker 版本會限制為本機存取，舊版例外見上一點。（來源：raw/01）

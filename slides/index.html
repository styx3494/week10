家用伺服器排查入門

家用伺服器連不上時，
怎麼一步一步排查？

兩個最常見的情況：

Docker 架的網頁打不開

容器明明在跑，別台電腦卻連不到。

NAS 的共用資料夾打不開

Windows 檔案總管連不上，或被拒絕存取。

操作：← → 鍵或下方按鈕翻頁。依據：wiki index

先建立一個比喻

房間與門

  • 容器像是住在主機裡的小房間，房門預設是關著的。
  • 連不上，通常是下面三種情況之一：

門沒開

沒有發布連接埠。

門只對自己開

只有主機自己連得到。

門口有人擋

沒有權限，或被封鎖。

依據：docker-port-publishing、docker-bind-address、nas-smb-checklist（一句話說明）

Docker 篇

Docker 的網路長什麼樣子

  • 容器預設就有網路，可以主動對外連線。
  • 沒有指定網路時，容器接在內建的 default bridge 網路上。
能對外連線，不代表外面連得進來。

依據：docker-network-basics

Docker 篇

開門：用 -p 發布連接埠

  • 沒有發布的連接埠，主機外面的裝置連不到。
  • 寫法是「主機連接埠:容器連接埠」：
-p 8080:80
   ↑     ↑
  主機   容器
  • 預設是 TCP；要 UDP 時寫成 -p 8080:80/udp。

依據：docker-port-publishing

Docker 篇

門開給誰：0.0.0.0 與 127.0.0.1

沒寫位址

-p 8080:80
發布到主機所有位址。原廠說這「預設不安全」：外面也連得到。

綁在 127.0.0.1

-p 127.0.0.1:8080:80
只有 Docker 主機自己連得到。

注意：Docker 28.0.0 以前，接在同一台交換器（同一個 L2 網段）的主機，仍可能連到綁在 localhost 的連接埠。

依據：docker-bind-address

Docker 篇

Docker 網頁打不開：排查三問

  1. 啟動時有沒有加 -p？
  2. 主機與容器的連接埠有沒有寫反？
  3. 是不是綁在 127.0.0.1，所以只有主機自己連得到？

依據：docker-port-publishing、docker-bind-address（常見誤解）

NAS 篇

SMB 是什麼？為什麼不要用 SMB1

  • SMB 是 Windows 開共用資料夾用的「語言」，有 SMB1、SMB2、SMB3 等版本。
  • SMB1 有重大安全弱點，微軟強烈建議不要使用；Windows 11 預設沒有安裝。
  • NAS 建議設定：最大 SMB3、最小 SMB2。

依據：smb-protocol-versions

NAS 篇

先查 NAS 端：檢查清單

以 Synology DSM 7 為例，其他品牌的選單名稱不同。

  • NAS 和電腦在同一個 LAN，NAS 有固定 IP（例如 192.168.1.50）。
  • 防火牆沒擋 137–139、445；已啟用 SMB。
  • 帳號有 SMB 權限與資料夾權限；不需要的 guest 帳號已停用。
  • DSM 7.2 以上：確認電腦的 IP 沒被自動封鎖。

依據：nas-smb-checklist

NAS 篇

再查 Windows 端

  1. 唯讀查詢分別用 IP 和名稱連線，比較結果：\\192.168.1.50\Public
  2. 唯讀查詢IP 可以、名稱不行：檢查 Reply from 後面的 IP 對不對。 
    ping <NAS 名稱>
  3. 可逆變更被拒絕：到認證管理員清除舊的 NAS 認證，之後要重新輸入帳密。
  4. 可逆變更有重複連線時，執行下面的命令。它會中斷所有網路磁碟機，之後要重新對應。 
    net use * /delete /y

依據：windows-smb-client-checks

為什麼會這樣

為什麼 Windows 擋掉訪客登入

  • 訪客登入就是：不用帳密就能開共用資料夾。
  • Windows 10 1709 起預設擋掉（Home、Pro 版有例外）；Windows 11 Pro 自 build 25267 起也預設擋掉。
  • 風險：可能被騙連到假的伺服器、遭勒索軟體入侵，或受到中間人攻擊。
微軟建議不要打開訪客登入。改用有權限的帳號，或更換只支援訪客登入的舊裝置。

依據：smb-guest-access

為什麼會這樣

Windows 11 24H2 的新門檻：SMB 簽章

  • 簽章就像是蓋在封包上的防偽章，證明內容沒有被竄改。
  • 24H2 起預設要求簽章：不支援簽章的第三方 SMB 伺服器、訪客共用、工作群組電腦，可能因此連不上。
  • 改用不同的 SMB 版本，不會改變簽章要求；也不要用停用簽章的方式繞過。

依據：smb-signing

別踩這些坑

三個常見誤解

✗ 容器跑起來了，網頁就一定打得開
✓ 沒有發布連接埠，外面就連不到。
✗ 連不上 NAS，就打開訪客登入
✓ 微軟建議不要這麼做。
✗ 升級 24H2 後連不上，打開 SMB1 就好
✓ 簽章要求跟 SMB 版本無關。

依據：docker-port-publishing、smb-guest-access、smb-signing（常見誤解）

總結

排查順序與安全原則

Docker

有沒有開門（-p）→ 門有沒有開對（順序）→ 門開給誰（綁定位址）

NAS

先查 NAS 端清單 → 再查 Windows 端

安全原則：不開 SMB1、不開訪客登入。要從外面連回家，原廠建議用 VPN，而不是在路由器設連接埠轉發。

依據：docker-port-publishing、docker-bind-address、nas-smb-checklist、windows-smb-client-checks、smb-protocol-versions、smb-guest-access
